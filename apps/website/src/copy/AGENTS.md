# Documentation Editing

- Give each guide a clear purpose. Link to the canonical explanation
  of a topic instead of copying it into multiple guides; retain enough
  local context to make examples understandable.
- Make examples runnable for the stated environment. Include necessary
  imports and setup, identify the test runner, and validate examples
  against executable tests where practical. Label incomplete excerpts.
- Explain when and why to use a pattern, including its limitations.
  Avoid presenting situational workarounds as universal rules.
- Verify version-sensitive claims against current official sources.
  Separate framework recommendations from project preferences.
- Preserve published heading anchors, or update links and search
  mappings that depend on them when reorganizing content.
- Edit canonical source content, not generated documentation copies.
  Check affected website, API, and CLI-facing output when changing
  guidance they share.
- Do not copy testing rules into these instructions. Refer to the
  shared testing skill and the relevant guide instead.
